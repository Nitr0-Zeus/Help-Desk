# Help Desk Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline, escolhido pelo usuário) para implementar tarefa a tarefa. Steps use checkbox (`- [ ]`) syntax.

**Goal:** SPA React consumindo a Help Desk API existente, sem alterar contratos do backend.

**Architecture:** Monorepo `frontend/` (Vite 5173 + proxy `/api`→8080) por domínio (`auth/`, `tickets/`, `metrics/`, `sla/`, `profile/`, `i18n/`, `components/{ui,layout}`); client HTTP tipado com refresh single-flight em `sessionStorage`; produção via `npm run build` → `src/main/resources/static/` servido pelo Spring (único ajuste backend: `SpaForwardConfig`).

**Tech Stack:** React 18, Vite, TypeScript strict, React Router, TanStack Query, Tailwind CSS, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-03-frontend-design.md` — decisões, contrato da API, direção visual e regras (tokens, refresh, guards, filtros-na-URL, anexos, i18n/tema).

## Global Constraints (da spec)

- **NUNCA** alterar contrato do backend; único cambio: `SpaForwardConfig`.
- Access + refresh em `sessionStorage`; nunca `localStorage` para tokens.
- Refresh single-flight centralizado no `api/client`: 401→refresh→retry 1×; falha → limpa sessão → `/login`; N-401 simultâneos = 1 refresh.
- Logout: limpa tokens independentemente do resultado do endpoint → invalida queries → `/login`.
- JWT no front = identidade/UX; backend = autorização (403).
- URL = estado dos filtros (`queryKey` inclui params).
- Anexos: UX valida espelhando API (10 MB/arquivo; whitelist png/jpeg/gif/pdf/txt/zip); backend é autoridade; download via fetch+Blob+createObjectURL.
- Sem libs além das aprovadas (React/Vite/TS/Router/Query/Tailwind/Vitest/Testing Library).
- 1 commit por tarefa (`feat:`/`fix:`/`chore:`/`docs:`); comandos PowerShell sem `&&`.
- i18n PT-BR/EN e tema claro/escuro seguem as decisões 9–10 da spec.
